## 一、项目概述

### 1.1 项目背景

随着【客户单位名称】业务系统规模与复杂度的持续增长，IT 运维面临以下共性挑战：

- **告警与监控分散**：监控告警、应用日志、链路追踪、资源指标分属多个独立系统，告警出现后需要在多个工具间来回切换取证，平均排障耗时长；
- **信息孤岛与经验断层**：排障经验依赖个人记忆，故障处理过程缺少沉淀，人员变动后同类问题重复排查；
- **变更与故障关联困难**：发布、变更与异常之间的因果关系难以快速还原，复盘成本高；
- **AI 能力尚未引入运维**：日常"查告警、翻日志、看指标、写结论"等重复性工作仍依赖人工完成，效率提升空间大。

> 注：本章痛点描述为通用运维现状表述，实施方将在需求调研阶段结合【客户单位名称】实际环境进行细化确认。

### 1.2 立项必要性

1. **统一运维入口**：将可观测性、事件中心、CMDB 拓扑收敛到统一平台，实现"看态势、找证据、问系统"的一站式运维闭环；
2. **引入 AI 提效**：通过 AIOps 智能助手，以自然语言驱动告警分析、日志取证、根因定位与结论生成，降低排障门槛、缩短平均处理时长；
3. **沉淀运维资产**：通过 Skill 技能包、Runbook 应急手册与全链路审计，将个人经验转化为组织资产；
4. **安全可控的 AI 落地路径**：平台遵循"模型负责理解、平台负责边界"原则——AI 只分析与建议，关键动作必须经权限校验与人工确认，为后续 AI 深度应用打下合规基础。

### 1.3 平台简介

SxDevOps 是面向真实运维现场的开源智能运维 Agent 平台，把可观测性、事件中心、任务中心、工单审批、容器管理、RBAC 等平台能力组织成 Agent 可调用、可审计、可确认的运维工作流。技术栈：Django + Django REST Framework + Channels + Vue 3 + Element Plus，Apache 2.0 开源协议。

平台核心能力与本项目范围的对应关系见「附录 A」。

## 二、建设目标

### 2.1 总体目标

建设一套面向【客户单位名称】的智能运维可观测性与 AIOps 平台，实现：

1. **看得全**：告警、日志、链路、指标、看板统一接入与集中展示；
2. **查得快**：跨源检索与关联跳转，AI 助手辅助取证分析；
3. **有沉淀**：故障处置过程、事件记录、审计日志完整留痕；
4. **可演进**：为后续任务自动化、审批执行类能力的扩展预留接口。

### 2.2 分项目标

| 阶段 | 目标 | 可验收标志 |
| ---- | ---- | ---- |
| 一期（基础可观测性） | 平台部署上线；告警、日志、指标、链路、看板基础能力可用；演示数据先行 | 平台稳定运行，功能清单核对通过，基础培训完成 |
| 二期（AIOps 智能体） | AI 智能助手上线：自然语言问答、告警根因分析、日志取证、待确认动作 | AI 问答核心场景通过验收，调用审计与成本统计可用 |
| 三期（深度集成与推广） | 按客户实际环境接入真实监控/CMDB 数据源；Grafana 看板嵌入；推广培训与试运行 | 真实数据源联通验证通过，试运行期无阻断性问题 |

### 2.3 建设原则

1. **平台是执行边界**：AI 模型只负责理解与规划，不直接操作生产资源；所有写入/执行动作必须经过权限校验、预检与人工确认；
2. **全链路审计**：会话、工具调用、模型调用、关键操作全程留痕，可回溯、可审计；
3. **安全优先**：后端 RBAC 强制校验（前端隐藏仅为体验优化）、凭据加密存储、最小权限原则；
4. **如实交付**：AI 能力依赖模型质量，平台通过结构化输出与证据约束抑制幻觉，但不对模型效果做绝对承诺。

## 四、总体技术方案

### 4.1 部署架构

```
┌──────────────────────────────────────┐
│         SxDevOps 应用容器             │
│  Daphne ASGI :8000                   │
│  ┌────────────┐  ┌────────────────┐   │
│  │ Django      │  │ Vue 3 前端      │   │
│  │ REST API    │  │ (静态文件)      │   │
│  └────────────┘  └────────────────┘   │
└──────────┬───────────────┬───────────┘
           │               │
    ┌──────▼──────┐  ┌─────▼──────┐
    │  MySQL 8.0  │  │  Redis 7   │
    │  :3306      │  │  :6379     │
    └─────────────┘  └────────────┘
```

- 部署方式：Docker Compose（应用 + MySQL 8 + Redis 7 三容器，参考部署文档 docs/00A）
- 服务器要求：2C4G 起、10GB 可用磁盘（正式环境按【待补充：规模评估】配置）
- 数据持久化：MySQL/Redis 数据卷持久化，定期备份

### 4.2 平台能力架构

平台按"事实层 → 理解层 → 行动层"组织：

```
事实层（可观测性）
  告警中心 / 日志中心 / 链路追踪 / 指标查询 / Grafana 看板 / 事件中心 / CMDB 拓扑
        │
理解层（AIOps 智能体）
  自然语言入口 → Action Router 任务分类 → Agent Mode（Direct/ReAct/Plan+ReAct）
  → Preflight 预检（权限/风险/缺参） → Skill/SOP 约束 → 工具调用取证
  → 二阶段结构化回答（结论/证据/风险/建议） → 待确认动作
        │
行动层（本期为预留）
  待确认动作 → 人工确认 → 平台 API 执行 → 审计留痕（任务中心/工单等执行模块为后续扩展）
```

### 4.3 外部系统集成路线

客户现状按"新建为主"规划，采用**演示数据先行、真实数据源按需接入**的策略：

| 阶段 | 数据源 | 接入方式 |
| ---- | ---- | ---- |
| 一期 | 平台演示数据（内置） | 平台自带丰富演示数据与离线看板，保障演示与培训不依赖外部系统 |
| 二期 | 模型 API（客户提供或采购） | 支持 OpenAI 兼容 API（DeepSeek/通义千问等），平台配置模型供应商 |
| 三期 | 客户真实监控/日志/CMDB（按实际环境） | Zabbix（API 对接）、Prometheus/Grafana（看板嵌入 + PromQL 代理）、Loki/ELK（日志）、iTop（CMDB 同步）等均有成熟接入能力，按客户实际存量系统逐项接入 |

> 说明：平台对上述外部系统均具备已实现的接入能力（含连接测试、数据同步、展示页面），三期具体接入清单以需求调研结果为准。

### 4.4 AI 模型接入方案

- **模型来源**：平台不捆绑特定模型，客户可选用 OpenAI 兼容 API 服务（DeepSeek、通义千问、智谱等）或私有化部署模型（Ollama/vLLM）；
- **成本透明**：平台内置模型调用审计与成本统计（Token 用量、预估费用、调用次数按会话归集）；
- **演示保障**：无模型 API 期间，平台支持离线模拟模式完成全部功能演示（不产生费用）；
- **安全边界**：模型仅用于理解与规划，不得绕过平台 API 直接操作资源；写入类动作必须人工确认。

### 4.5 安全与权限设计

- **RBAC**：权限码后端强制校验，支持角色/用户组管理（平台管理员、运维管理员、研发、审计员、只读等内置角色）；
- **审计**：登录、配置变更、AI 会话、工具调用、模型调用、关键操作全部留痕（智能体审计、操作审计、事件墙）；
- **凭据安全**：外部系统凭据加密存储，接口不回传明文；
- **生产基线**：SECRET_KEY 随机化、DEBUG=0、ALLOWED_HOSTS 限制、默认口令修改。

## 七、验收标准

### 7.1 一期验收（基础可观测性）

1. 平台部署完成，持续稳定运行【待补充：连续运行天数】天无异常宕机；
2. 功能清单（附录 A 中 F1-F7、F11）现场演示逐项核对通过；
3. 演示数据完整（告警、日志、链路、看板、事件、拓扑均有数据展示）；
4. 交付文档齐全：部署文档、用户手册、配置基线说明；
5. 基础培训完成且考核通过（管理员/使用人员）。

### 7.2 二期验收（AIOps 智能体）

1. AI 智能助手核心场景现场演示通过：告警查询与分析、日志取证、Zabbix/CMDB 查询、待确认动作生成与确认流程；
2. 回答遵循结构化输出（结论/证据/风险/建议），证据可溯源到平台数据；
3. 模型调用审计与成本统计页面可用，数据准确；
4. Skill/Runbook 定制清单交付并经客户确认。

### 7.3 三期验收（深度集成与推广）

1. 确认接入的真实数据源全部连通（连接测试通过、数据正常展示）；
2. Grafana 看板嵌入正常（目录同步、iframe 渲染、自动刷新）；
3. 试运行期【待补充：试运行周期】内无阻断性问题，遗留问题清单双方确认闭环计划；
4. 推广培训完成，一线使用人员具备独立使用能力。

### 7.4 验收方式

- 现场演示：按功能清单逐项演示；
- 文档核验：交付文档完整性检查；
- 试运行：试运行期问题跟踪表作为验收依据之一。
