### 2. 关联性（★★★★★，强项）

- 告警 → 主机关联率：**40/40 = 100%**（经 `zabbix_hostid → Host.external_id` 关联键）
- Zabbix ↔ iTop 设备映射覆盖率：**18/18 = 100%**
- 告警 environment 统一为数据源名「奇点运维监控系统」，无空值

### 3. 规范性（★★☆☆☆，主要短板）

| 缺口 | 影响 | 严重度 |
| ---- | ---- | ---- |
| 知识环境 `zabbix_datasource_ids` 未绑定（空数组） | 单源时靠全局默认兜底可工作；**多数据源环境必选错源**；不符合绑定规范 | ❌ 高 |
| `event_environments=['默认']` 与 `alert_environments=['奇点运维监控系统']` 不一致 | 事件中心/图谱按环境过滤与告警不对齐，跨模块关联漏数据 | ⚠️ 中 |
| Zabbix 同步主机 `business_line`/`environment` 18/18 全空 | 知识图谱按环境/业务线归属失效，AI 按业务线分析受限 | ⚠️ 中 |
| CMDB `business_line` 33/34 为空（iTop `org_name` 未维护） | CMDB 拓扑业务归属缺失，影响按业务线的变更影响分析 | ⚠️ 中 |
| 事件墙 555 条 ops 事件堆积（每轮轮询的 update 均记录事件，无去重/滚动保留） | 事件噪音大，故障窗口检索效率下降 | ⚠️ 低 |

### 4. 时效性（★★★★★）

- Zabbix 轮询：内置调度 5 分钟（`SXDEVOPS_ZABBIX_POLL_INTERVAL=300`），最新告警 3 分钟内
- iTop 同步：手动触发（`last_sync_at` 正常更新）
- 无陈旧数据迹象

## 三、高质量运行数据标准

### 必达（部署验收时逐项核对）

| 编号 | 标准 | 测量方法 |
| ---- | ---- | ---- |
| S1 | 知识环境六项绑定齐备：zabbix / metric / log / tracing / task_resource / alert_environments 全部非空且指向启用数据源 | 图谱配置页核对，或 `AIOpsKnowledgeEnvironment` 记录检查 |
| S2 | 告警 → 主机关联率 ≥ 95% | `Alert(source_type='zabbix', host__isnull=True)` 占比 |
| S3 | Zabbix ↔ iTop 设备映射覆盖率 ≥ 90% | `DeviceMapping` 数与 Zabbix 主机数之比 |
| S4 | 全部数据源启用且健康（测试连接成功 / /ready 200） | 数据源管理页逐项测试 |
| S5 | Zabbix 告警轮询 ≤ 5 分钟（内置调度运行、last_sync_at 新鲜） | 后端日志 `zabbix poll done` 周期检查 |
| S6 | 告警 environment 与知识环境 alert_environments 语义一致（无空值、无双写） | 抽查 Alert.environment 集合 |

### 建议（提升分析效果）

| 编号 | 标准 | 说明 |
| ---- | ---- | ---- |
| S7 | 主机/CI 的 business_line 标注覆盖率 ≥ 80% | Zabbix 侧按主机组映射，或平台侧配置默认业务线；iTop 维护 org_name |
| S8 | `event_environments` 与 `alert_environments` 对齐 | 保证事件/告警跨模块可联合过滤 |
| S9 | 事件滚动保留策略（如 7 天）与导入去重 | 控制事件墙噪音（当前每轮轮询的 update 均记事件） |
| S10 | 多数据源时验证「环境同名优先」解析规则 | `_resolve_zabbix_datasource` 绑定解析 |

### 可选

- 告警确认率基线（当前 0 确认）；Zabbix 主机标签/组到业务线的自动映射增强。
