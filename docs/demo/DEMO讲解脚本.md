# SxDevOps 客户现场演示讲解脚本

> 总时长约 20-25 分钟。所有数据均为离线模拟数据，AI 问答由内置模拟模型引擎驱动（真实调用平台工具、真实查询演示数据、按模板生成结构化答案）。

---

## 零、开场（1 分钟）

**一句话定位**：SxDevOps 是面向运维现场的开源智能运维 Agent 平台——把可观测性、事件中心、任务中心、CMDB、容器管理与 RBAC 收敛成 Agent 可调用、可审计、可确认的运维工作流。

**贯穿全场的故事线**：生产环境 order-center（订单中心）v2.6.3 灰度发布后库存校验超时——从发现告警、取证分析、定位根因，到生成处置任务的完整闭环。

---

## 一、登录与总览（2 分钟）

1. 打开 `http://localhost:8000`，用 **admin / Admin@123456** 登录
2. 讲解仪表盘：平台总览、系统态势统计卡（告警数、主机数、任务数）
3. 点右下角悬浮的 AI 助手，介绍「任意页面可唤起」

---

## 二、告警中心 → 日志中心（3 分钟）

**告警中心**（侧边栏：可观测性 → 告警中心）：
- 展示 3 条 order-center 相关告警：`库存校验超时`（严重）、`下游依赖重试激增`（严重）、`发布后健康检查失败`（警告）
- 讲解：告警与主机、业务线关联；严重级别优先

**日志中心**：
- 检索 `Inventory service timeout`，展示错误日志：`Inventory service timeout while creating order ORD-20260410-1024`、`retry storm after inventory timeout`
- 讲解：告警 → 日志的取证链路

---

## 三、事件墙与应用发布（3 分钟）

**事件墙**：17 条近 7 天事件（默认展示最近 1 小时，讲解时把时间范围切到「近 7 天」查看完整事件流），按模块/环境/应用过滤，演示「关键操作留痕」
**应用发布**：展示 `订单中心生产发布后库存校验超时` 发布单——灰度批次、审批流、失败状态与回滚入口

---

## 四、CMDB 拓扑与知识图谱（3 分钟）

**CMDB**：22 个配置项、14 条拓扑关系，按业务线（电商平台/数据平台/基础架构）过滤
**拓扑图**：order-center → order-db / inventory-service 依赖链，拖拽交互
**知识图谱**（AIOps → 知识图谱）：展示 环境 → 系统 → 服务 → 组件 → 基础设施 分层节点与关系边
**Zabbix 监控页**：演示数据源 6 台主机、监控项图表（order-api-ecs-01 磁盘使用率 >90%）、2 条活跃问题

> 讲解词：**这些页面是"事实层"，接下来看 Agent 如何自己调用它们。**

---

## 五、AI 智能助手 6 连问（核心，8 分钟）

进入 AIOps → 智能助手（或右下角悬浮窗）。每问讲一句「看它的工具调用过程」。

### Q1. 生产环境当前有哪些告警

- 触发工具：`query_alerts_tool`（真实查询告警表）
- 预期回答：**结论**（10 条告警、5 条严重）+ **关键证据**（逐条列出）+ 建议操作
- 讲解点：二阶段结构化答案；结论不编造、证据可溯源

### Q2. 分析 order-center 库存校验超时的根因

- 触发 Action Router：`alert.root_cause`（告警根因分析）
- 触发工具：`query_alert_root_cause_tool`
- 预期回答：根因结论（灰度发布后库存服务响应超时）+ 告警/日志/变更证据链 + 风险与建议
- 讲解点：Action Router 识别任务类型 → 选择 Agent Mode → 工具白名单

### Q3. 查一下 order-center 最近的错误日志

- 触发工具：`query_logs_tool`
- 预期回答：错误日志条目 + 关联告警建议
- 讲解点：取证类问题直达事实

### Q4. Zabbix 上有哪些严重级别的磁盘问题

- 触发工具：`query_zabbix_problems_tool`（查询演示 Zabbix 数据源）
- 预期回答：[严重] order-api-ecs-01 磁盘使用率超过 90% + 处置建议
- 讲解点：外部监控系统接入为工具；离线演示数据源

### Q5. 帮我生成一个对订单相关主机的巡检任务 ⭐

- 触发工具：`query_zabbix_hosts_tool` → 找到 order-api-ecs-01/02
- **出现"待确认动作"卡片**：订单服务主机巡检任务（低风险）
- 点击**确认** → 任务中心出现任务草稿（含 2 台目标主机与巡检脚本）
- 讲解点（本场高潮）：**模型只负责理解与规划，平台负责边界**——写入动作必须预检 → 人工确认 → 平台 API 执行 → 审计留痕

### Q6. CMDB 里订单中心依赖哪些系统

- 触发工具：`query_cmdb_topology_tool`
- 预期回答：上游依赖/下游被依赖清单 + 变更风险提示
- 讲解点：依赖影响分析场景

## 六、收尾展示（3 分钟）

1. **智能体审计**（AIOps → 智能体审计）：刚刚 6 问的模型调用记录（`sxdevops-demo-mock`）、工具调用记录、Token 统计——「全链路可审计」
2. **Skill 技能包 / Runbook**：演示内置 SOP 与应急手册
3. **任务中心**：Q5 确认后的巡检任务草稿
4. **RBAC 演示**（可选）：退出登录换 `viewer_demo` 演示只读权限、菜单与按钮级权限差异
5. **工单 / SQL 审计 / 多云资产**：静态展示各模块演示数据

---

## 七、结束语建议

> SxDevOps 的核心理念：**模型负责理解，平台负责边界**——Agent 可以分析、生成草稿，但每一次关键动作都经过权限校验、人工确认和审计留痕。平台今天演示的全部是离线模拟数据；对接真实环境时，只需在平台上配置 Zabbix / iTop / Prometheus / K8s 等数据源与模型 API，同样的工作流即可作用于真实基础设施。
